# 逐句 · 直播字幕延迟分布与节目复盘

街巷广播社有 9 人轮班制作街坊访谈直播。当晚的字幕质检员将节目单、导播源录音和直播回放对齐，确认迟到的句子交给补字幕编辑。此前三处问题最费时间：中位数看不出片尾的集中迟到，文件群里散落的时码无法对齐同一节目段，交接时缺少源录音或样本覆盖仍有可能被标成完成。这里把这些条件纳入节目段的校对流程，签收后的字幕文件引用交给回看节目编目员。

| 角色 | 典型页面 | 权限 |
|---|---|---|
| operator · 字幕质检员 | 节目单、锚点时间轴、延迟诊断、补字幕交接 | 挂接源录音、登记抽样锚点、计算分布、开工作包、提交补字幕 |
| reviewer · 回看复核员 | 锚点时间轴、延迟诊断、补字幕交接 | 核对覆盖与时间码，退回或签收补字幕 |
| viewer · 节目编目员 | 四个页面 | 查看节目单、诊断和签收文件引用 |

## 值班剧本

1. 19:30，《街巷开麦》的手艺人圆桌段 `AFTER-01` 开播。抽样计划要求 8 个锚点，每句上屏预算 1,800 ms。
2. 19:34，质检员把回放中的 6 个锚点对入语音时间轴，发现 83、93 和 107 秒附近的三句掉队。
3. 19:35，诊断得到 P90 为 5,200 ms、超标率 50%、尾段 3 条超时，指定 01:21.000 至 01:49.000 的补字幕窗。
4. 19:37，补字幕编辑领取范围。源录音尚未挂接，第一次提交 `AFTER-01-v1.vtt` 被拦下。
5. 19:43，节目单挂接 `roundtable-master.wav`。覆盖 6/8 仍不足 80%，在 115,000 ms 补齐第七条锚点，再生成诊断。
6. 19:47，覆盖 7/8。字幕编辑送审 `AFTER-01-v1.vtt`，时间码与录音引用冻结。
7. 19:51，复核员发现末句和背景音重叠，退回工作包补说话人标签。
8. 19:56，编辑交 `AFTER-01-v2.vtt`，复核员签收，回看编目员查看签收文件名。

演示启动时提供圆桌、街坊来信和片尾值守 3 段，共 16 个锚点。后两段展示准时和整体偏慢两种分布，片尾段已有待接单工作包。

## 分析口径和限制

延迟为上屏时间减语音时间，负值表示提前上屏。ECDF 在每个唯一延迟值累加观测占比，P50 与 P90 用 nearest-rank 取有序样本的第 `ceil(p × n)` 项。严格超过该段 SLA 的锚点算迟到。将节目时长分三等段，若至少两条迟到且其中 75% 或以上集中于同一段，记为集中掉队。否则至少一半锚点迟到记为整体偏慢。有迟到但比例较低记为个别超时。其余记为准时。工作包的时间窗为最早至最晚迟到语音点，两侧加 2 秒并裁切到节目长度。

少于 5 个锚点不计算。后台任务按锚点版本运行，过期结果不会覆盖当前版本。交接要求源录音和至少 80% 的锚点覆盖。每个节目段允许一条可退回修订的补字幕工作包。演示以文件名引用外部素材，实际听审和字幕文件保存由编辑工作站完成。

## 整档时限调整

值班台可对整档节目收紧或放宽上屏时限：提交后为每个节目段按新时限在后台重算延迟诊断，全部就绪才在一个事务里切换各段的时限与诊断，任何一段失败则整档保留旧版。重算期间锚点照常修订，改过的节目段按最新锚点重新计算。同一申请按申请键重试返回既有发布，不新增版本；同一节目同时只有一个进行中的发布。切换前开单的补字幕工作包按旧版诊断划定范围并保留开单依据，切换后新开的工作包按新版诊断划范围。延迟诊断页展示当前生效时限和最近一次发布的进度。

## 运行

```sh
cp .env.example .env
docker compose up -d --build --wait
docker compose exec -T backend python -m scripts.seed_demo
```

| 用途 | 默认入口 |
|---|---|
| 前端 | http://127.0.0.1:18282 |
| FastAPI 文档 | http://127.0.0.1:19282/docs |
| PostgreSQL | 127.0.0.1:17782 |

演示账号为 `operator@demo.local`、`reviewer@demo.local`、`viewer@demo.local`，默认密码均为 `Demo2026!`。前端登录表单提供账号角色下拉。修改演示密码可在第一次建库前设置 `DEMO_PASSWORD`。其他环境变量见 `.env.example`，包括三个宿主机端口、`COMPOSE_PROJECT_NAME`、`POSTGRES_PASSWORD`、`JWT_SECRET` 与 `SEED_DEMO`。

| 层 | 实现 |
|---|---|
| Web | Nginx 静态文件与 API 反代、原生 HTML/CSS/JS 模块 |
| API | Python 3.12、FastAPI、Psycopg、JWT |
| 后台 | PostgreSQL 持久队列和 Python Worker，Redis 登录频控及连通性检查 |
| 数据与配置 | PostgreSQL 16、Redis 7、Compose 五服务与命名卷 |

本地开发时运行数据库和 Redis，给后端进程传入 `DATABASE_URL`、`REDIS_URL`、`JWT_SECRET` 和 `SEED_DEMO=true`，进入 `backend` 安装 `requirements.txt` 并执行 `uvicorn app:app --reload` 和 `python worker.py`。前端开发以同源 `/api/` 代理运行。Compose 可用 `docker compose stop` 保留数据，测试后可用 `docker compose down -v` 删除该项目的演示卷。

- `backend/schema.sql` 定义节目段、锚点和补字幕包。
- `backend/domain.py` 管理 API、权限、输入 schema 和演示 fixture。 `subtitles.py` 实现带锁工作流，`timing.py` 实现延迟诊断。`sla_service.py` 与 `sla_api.py` 实现整档时限的暂存重算与原子切换。
- `frontend/cues.js` 管理节目段选择、接口路径、业务组件及时间码格式，`studio.js` 提供四个页面的操作。
- 共享枚举有账号角色（`backend/core.py`、`frontend/base.js`、本页权限表）、后台状态（`backend/core.py`、`backend/worker.py`、`frontend/base.js`）、补字幕状态（`backend/schema.sql`、`backend/subtitles.py`、`frontend/cues.js`、`frontend/studio.js`）、延迟模式（`backend/timing.py`、`frontend/cues.js`、`frontend/studio.js`）和时限发布状态（`backend/migrations/040_sla_release.sql`、`backend/sla_service.py`、`frontend/studio.js`）。

## 屏显到复盘

补字幕签收后的片段可继续留下用于交付复核的锚点轨道样本。录入员为每个锚点记录说话人、收声通道和实际显示毫秒。质检按显示时间检查缺标、越界、重叠和字/秒超限，字数去掉空白并包含说话人标签。通过后由复核员签当前版本，录音引用、锚点或标注有变化须重新出单。

字幕样本轨引用签过的质检数据。源录音须已登记，有补字幕工作包则先完成签收。复核员签发后可下载 WebVTT 和查看 SHA-256。已经签发的旧轨保留存档。该导出覆盖已抽样锚点，正式整场字幕仍由既有编辑工作站交回。

当前诊断有超时锚点时，录入员用与当前质检一致的已签样本轨开复盘事件，保存改进措施与原始超时范围。全数 replay 延迟不超过该段 SLA 后可签结案。三块业务数据在启动时追加迁移，可用于旧数据库。
